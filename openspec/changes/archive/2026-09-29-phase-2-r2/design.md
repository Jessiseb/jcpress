# Design: phase-2-r2

## Context

动机见 `proposal.md - Why`。这里只记实施前实测到的**约束与事实**：

| 事实 | 数值 / 出处 |
| --- | --- |
| 流线被拉伸的倍数 | x = 视口宽 / 696、y = 视口高 / 316；1280×900 下是 1.84 / 2.85（`preserveAspectRatio="none"`，`FlowField.module.css` 的 `.svg`） |
| 实际线宽 | `strokeWidth 0.5 → 1.55`（viewBox 单位）× 拉伸 ≈ **0.9 → 2.9px** |
| 实际剂量 | 描边不透明度 ≤ 0.5（`--ds-flow-alpha-max`）× 层呼吸 0.78–1 → **屏上 ≤ 0.5** |
| 正文与线的取色 | 正文主色 `#3c3c43`；条目名用 `--ds-c-text-mute` = `rgb(60 60 67 / 78%)`；线色 `#0f172a` @0.5 → 三者明度都在中灰带 |
| 路径数分档 | 桌面 36×2 = 72 / 平板 24×2 = 48 / 手机 12×2 = 24 |
| 入场参数 | 位移 18px、时长 460ms、错峰 60–80ms（`global.css` 的 `[data-reveal='on'] [data-reveal]`） |
| 既有硬约束 | 零网络请求；单条流线只允许一条 CSS 动画（`decisions.md` #51）；`reduced-motion` 完全静止；`data-reveal` 只在 HomePage 子树内（#31）；技术栈不得用点阵/进度条（homepage spec） |

## Goals / Non-Goals

**Goals**

1. 把流线从「满屏灰带」改成「**细、少、品牌蓝**的淡纹」：白天形态下不抢字、不眼花。
2. 正文与流线**分族**（字近黑、线蓝淡），且这条分离**可量化验收**，不靠"看着清楚"。
3. 入场有可感的「闪出」，但只动 `transform` / `opacity`，不引入新的每帧成本。
4. 区块顺序改为「经历优先」，并让大小节节奏仍然交替。
5. 三块（技术栈 / 获奖 / 联系）各自有一个**版式主角**，不再停留在规格表。

**Non-Goals**

- 不引入新字体、新依赖、新颜色语义；不恢复点阵/进度条（一期硬条款）。
- 不改数据字段与文案口径（`dt=4`、五项奖项、三段经历等断言口径不动）。
- 不做「逐字擦出 / 视差式标题」这类重动效（对应用户的「也不用很重」）。
- 不改内部页（`/tech`、`/algo`、404）的排版。

## Decisions

### D1 · 线宽用 `vector-effect="non-scaling-stroke"`，而不是反算拉伸比

`preserveAspectRatio="none"` 下 x / y 拉伸比不同，任何以 viewBox 为单位的线宽都不可能同时在两个方向上等于目标像素值。
**替代方案**：(a) 按 x 拉伸比反算线宽——y 方向仍然不对，且视口一变就得重算；(b) 放弃拉伸、改回 `meet`——会在宽屏留空带、手机竖屏压成细带（二期已实测舍弃）。
选 `non-scaling-stroke`：线宽以**设备像素**为单位，与变换无关，视口怎么变都是目标粗细（Chromium/Firefox/Safari 均支持）。

### D2 · 线色改品牌蓝、剂量压到 0.28、数量 48/32/16

- 线色：亮色用品牌蓝 `#0a6fd8`（`--ds-c-accent-bg` 一档），暗色用 `#4d9bff`（暗色 accent）。**不再用 `#0f172a`** —— 它正是"与正文同族"的根源。
- 剂量：`--ds-flow-alpha-max` 0.5 → **0.28**；单条描边的目标值区间 0.16–0.5 → **0.06–0.28**。
- 数量：`TIERS` 36/24/12 → **24/16/8**（总路径 48/32/16）。降数量是"少"的直接手段，而**动画条数**的硬约束（D8）不变（每条仍只有一条动画）。

### D3 · 正文色调分层：字近黑、线蓝淡

`--ds-c-text` 由 `#3c3c43` 改为近黑（`#17181c`）；`--ds-c-text-mute` 由 78% → **88%**；`--ds-c-text-subtle` 由 56% → **74%**（暗色三档同步微调）。
理由：正文与条目名是**内容主体**，弱化应当只用于出处、单位、元信息这类真正的次级信息；而不是让主体也落进中灰带、与背景纹理撞车。既然两条都要满足 AA，加深只会让审计更宽松（不存在"为了好看牺牲对比度"）。

### D4 · 入场加强的参数边界

位移 18 → **28px**，并加 `scale(0.985)` → `scale(1)`；时长 460 → **520ms**；错峰保持 60–120ms 区间（现为 70/80ms）。
**只动 `transform` / `opacity`**：这两项走合成器；一旦动 `filter` / `clip-path` / `height`，就会把二期刚修好的移动端性能（`decisions.md` #51）重新拖下水。
`[data-reveal='on']` 的 JS 门控与 `reduced-motion` 直接不接管两条纪律**原样保留**（不拿 SEO 与降级换动效）。

### D5 · 三块版式（各自一个主角）

| 区块 | 主角 | 具体做法 |
| --- | --- | --- |
| 技术栈 | **组名** | 组名进固定左栏（展示衬线、比正文大一档），技能以流式词组排右栏，档位是名字旁的极小文字标记；组与组之间仍用通栏发丝线（保持一期「对齐即秩序」的分块语言） |
| 获奖经历 | **年份** | 年份用展示衬线、明显大于奖项名，纵向对齐成一列形成时间轴；奖项名与等级分列其后 |
| 联系我 | **邮箱** | 邮箱用展示衬线大字号作主入口（`mailto:` 可点）；微信 / Gitee / CSDN / 知识库降为次级条目一行排开；一键复制与「手机号不上站」两条不动 |

替代方案：给三块加卡片 / 徽章 / 编号 —— **否**。卡片化是一期明确否掉的反模式（#46），编号只适用于真正的序列（技术栈分组不是序列、奖项是时间序列但已有年份轴）。因此三块的主角都从**内容本身**（组名 / 年份 / 邮箱）里选，而不是外挂装饰。

### D6 · 区块顺序与节奏重排

新顺序：`首屏 → 关键数字(M) → 实习经历(m) → 项目经历(M) → 技术栈(m) → 教育与荣誉(M) → 联系我(m)`。
- 「经历优先」：访客 30 秒内要看到"做过什么"，能力清单是佐证、不是开场。
- 节奏仍严格交替（M/m），与一期「大节 / 小节交替」的契约一致；**面板仍只给「关键数字」与「项目经历」**（后者仍是 M，与面板语义兼容）。
- 断言口径：六个 `h2` 的**文本集合**不变，新增一条**顺序**断言。

## Risks / Trade-offs

| 风险 | 缓解 |
| --- | --- |
| `non-scaling-stroke` 在极窄屏让线看起来偏粗（因为不再随缩放变细） | 线宽档仍按视口分档（0.6 / 0.85 / 1.1px），并在 390 与 1280 两档各出一张裁图对照 |
| 剂量降到 0.28 后"图案修饰"变弱，可能从"眼花"跳到"看不见" | 剂量与数量是**两个独立旋钮**：先各降一档出图；若观感偏弱，优先加回数量而不是加回浓度（数量不伤可读性） |
| 正文加深后暗色主题的字过亮/刺眼 | 暗色三档灰阶同步微调，并复跑对比度审计（亮暗各约 240 处） |
| 三块重做后原有断言亮红（`dt`/`h3`/奖项行数/触摸目标/无溢出） | 重做时**不改语义元素与数据**：仍是 `dl`/`dt`/`dd`、仍是 `h3`、奖项仍 5 行；改完立刻跑 51 项断言 |
| 顺序调整破坏「大小节交替」 | 顺序与节奏一次改完，断言里同时查"两档差 ≥24px"与"相邻不同档" |

## Migration Plan

1. 用户已选择「先做出来看效果」，本轮**跳过计划评审 gate**（proposal/design/specs/tasks 与实现同批产出）。
2. 实施顺序：令牌（线色/剂量/灰阶）→ 流线层（数量/线宽/颜色）→ 入场参数 → 顺序与节奏 → 三块版式 → 断言同步 → 全量验收出图 → 归档 + 留痕。
3. 回滚：每个文件组的改动都能独立 `git revert`；spec 在归档前不影响主干。
4. 主干 spec 同步：实施验收后用 `openspec archive phase-2-r2`。
