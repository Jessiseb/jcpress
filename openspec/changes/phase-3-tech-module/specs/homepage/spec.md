# Spec Delta

## MODIFIED Requirements

### Requirement: 重点区块的面板化

首页 SHALL 只对「关键数字」「项目经历」「技术栈」三类区块使用面板容器（玻璃底色 + 圆角 + 边框）；其余区块 SHALL 保持通栏，SHALL NOT 使用面板底色或投影。面板 SHALL NOT 承载唯一的信息分层——去掉面板后信息仍 SHALL 完整可读。

**为什么技术栈在第三类**：这一节是 6 个方向 × 28 项的**并列清单**，没有叙事顺序，面板把它收成「一个可一眼扫完的对象」；而教育与荣誉、联系我都是线性文本，加了面板只会多一层壳。判定按 `data-glass` 标记而不是区块名。

**例外（且只有这一个）**：实习经历作为「整幅特写」SHALL 允许其正文里存在**一块**带底色与投影的容器（左图 + 右文的那张卡）。判定按 `data-full` 标记而不是区块名，且该区块的正文子元素 SHALL 恰好为两块（切换条 + 卡片）、带面的 SHALL 恰好为一块 —— 避免它变成「每个区块都能包卡片」的后门。

**三期新增的「最新技术分享」区块不属于三类面板区块**：它 SHALL 保持通栏、以行式列表呈现（标题 + 日期 · 阅读时长），SHALL NOT 使用卡片底色、圆角容器或投影。卡片形态的破例范围**只在** `/tech` 列表页与文章详情页（见 `tech-article-list` 与 `tech-article-detail`），SHALL NOT 扩散到首页。

#### Scenario: 面板只出现在三类区块

- **WHEN** 统计页面上带面板标记的容器
- **THEN** 它们只位于关键数字区、项目经历区与技术栈区

#### Scenario: 其余区块保持通栏

- **WHEN** 检查其余区块（除 `data-full` 的整幅特写外）的容器样式
- **THEN** 它们没有面板底色与投影

#### Scenario: 整幅特写只许一块面

- **WHEN** 检查带 `data-full` 标记的区块
- **THEN** 页面上这样的区块只有一个，其正文恰好两块，其中恰好一块带底色或投影

#### Scenario: 面板不承担唯一信息层次

- **WHEN** 在忽略面板样式的条件下阅读关键数字区与项目经历区
- **THEN** 指标名、数值、出处与项目详情仍然完整可读、可展开

#### Scenario: 最新技术分享区块不是卡片墙

- **WHEN** 检查「最新技术分享」区块内每个条目的容器样式
- **THEN** 它们没有卡片底色、圆角容器或投影，只有标题与"日期 · 阅读时长"

### Requirement: 区块顺序

首页的区块顺序 SHALL 为：首屏 → 关键数字 → 实习经历 → 项目经历 → **最新技术分享** → 技术栈 → 教育与荣誉 → 联系我。「经历类」与「产出类」区块 SHALL 排在「能力清单类」区块之前。

#### Scenario: 经历排在能力之前

- **WHEN** 按文档顺序读取首页各区块的二级标题
- **THEN** 顺序为 拿得出手的数字 → 实习经历 → 项目经历 → 最新技术分享 → 技术栈 → 教育与荣誉 → 联系我

#### Scenario: 首页区块数与停靠表一致

- **WHEN** 统计首页带 `aria-labelledby` 的区块数量
- **THEN** 该数量与天体停靠表（`data-scene` 规则）的档数一致，每个区块都有对应的停靠位置
