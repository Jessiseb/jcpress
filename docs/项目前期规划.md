## 1. 项目定位与范围

### 1.1 定位

一个**个人品牌站**，同时承担三件事：

1. **简历的延伸**：一页说清我是谁、做过什么、会什么（关于我）
2. **知识沉淀的容器**：技术分享按分类组织，项目笔记按项目组织
3. **生活经验（暂不实现）**：留作后续扩展，届时用隐藏链接或共享口令控制可见性（备选方案见 [附录 C](#附录-c生活经验可见性备选方案)）

### 1.2 成功标准（第一期）

一个陌生人打开首页 30 秒内知道我是谁、能顺畅读到任意一篇技术文章；
站点**前台全站公开、无需登录**；后台管理系统需要账号登录，未授权者改不了任何内容。

### 1.3 第一期做

- 3 个内容频道：关于我 / 技术分享（按分类）/ 项目笔记
- 站点级能力：顶栏导航（含下拉）、明暗主题、搜索、404、响应式
- **前台无登录、无账号体系**：访客全站公开可读，不需要注册，也没有内容可见性分级
- **后台管理系统需要账号登录**：认证与权限用 **Sa-Token**（见 [§8](#8-访问控制) 与 [§15 D9](#15-待确认决策)）
- 内容录入：Markdown 导入器（M1）+ 后台写入口（M5）；**完整管理后台放在二期**（见 [§10](#10-后台管理系统) 与 [§15 D8](#15-待确认决策)）

### 1.4 第一期不做（明确排除，防止范围蔓延）

- 评论 / 点赞互动社区（仅保留浏览量）
- 多作者、投稿、审核流
- 移动 App、小程序
- 全文检索集群（ES）—— MySQL 全文索引 + Redis 缓存足够
- 推荐算法、埋点分析平台
- **生活经验频道**（暂时不做；若恢复，见 [附录 C](#附录-c生活经验可见性备选方案)）
- **前台的账号体系**：访客注册 / 登录 / 用户中心 / 内容可见性分级（**后台账号登录是需要的**）
- **完整的文章 / 分类 / 项目管理后台**（一期只做导入器 + 一个写入口，见 [§10](#10-后台管理系统)）

## 2. 设计基线（提取自 golangstar.cn）

### 2.1 提取说明与证据边界

| 项目 | 内容 |
| --- | --- |
| 目标站 | `https://golangstar.cn/`（个人技术知识库站，站名"秀才的进阶之路"） |
| 目标站技术栈 | VuePress 2.0.0-rc.19 + VuePress Theme Hope 2.0.0-rc.66 |
| 许可 | 两套依赖均为 **MIT**（已核对 npm registry 的 `license` 字段） |
| 方法 | `extract-design-system`（dembrandt 计算样式提取）+ 对站点样式表 CSS 变量层的手工解析 + 文章页 DOM 采样 |
| 证据文件 | `.extract-design-system/raw.json`（最完整）、`design-system/tokens.curated.*`（整理后）、`design-system/tokens.*`（工具原始输出） |

**能证明什么**：颜色、字号、间距、圆角、阴影、布局宽度、断点、组件形态 —— 均有 DOM/CSS 声明或计算样式支撑。

**不能证明什么**：这是一次**代码层**还原，不是像素级截图比对；只采了**首页 + 一篇文章页**两个页面，
不代表完整设计系统；评论组件、搜索弹窗内部、打印样式未覆盖。视觉观感需人眼确认。

> ⚠️ 自动提取工具对这类"CSS 变量驱动"的站点效果很差：页面里 `--vp-c-accent` 写成
> `rgb(7.1084070796, 86.0907079646, 171.3915929204)` 这种小数形式，工具只识别出 **1 个主色**，
> 且没有提取到圆角与阴影刻度。因此补了一遍对样式表的解析，`tokens.curated.*` 才是可用基线。

### 2.2 视觉语言总览

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 主色 | 单一蓝色 `#096fdc`（hover `#0a7bf5`，实心 `#0756ab`） | 全站只有一个强调色 |
| 中性色 | 白底 `#fff` / 浅灰 `#f6f6f7`，正文 `#3c3c43` | 正文非纯黑，用暖调深灰 |
| 状态色 | grey / blue / green / yellow / red / purple / indigo，每色 4 档 | soft 档统一 14% 透明度 |
| 主标题 | 3.6rem / 700 / 行高 1.5，**蓝→紫渐变文字** | 全站唯一情绪化设计 |
| 正文宽度 | 780px | 中文长文舒适上限 |
| 圆角 | 卡片 8px、代码块 6px、媒体 10px、胶囊 40px | 克制，不做大圆角卡片 |
| 阴影 | 极轻 `0 2px 8px rgb(0 0 0 / 5%)`，hover 才明显 | 靠 hover 提亮 |
| 动效 | 统一 `0.3s ease`，hover 上移 1px | 只做呼吸感 |
| 主题 | 完整 light/dark 双套 token，`[data-theme=dark]` 切换 | — |

**一句话概括**：冷静、克制、内容优先的文档型技术博客 —— 白底、单一蓝调、小圆角、轻阴影、大留白。

### 2.3 颜色 token

**Light**

| Token | 值 | 用途 |
| --- | --- | --- |
| accent | `#0756ab` | 链接、引用左边框、激活导航项 |
| accent-bg | `#096fdc` | 实心按钮 / 强调块 |
| accent-hover | `#0a7bf5` | hover、focus 环 |
| accent-soft | `rgb(20 99 184 / 14%)` | 选中底纹、badge |
| bg / bg-alt | `#fff` / `#f6f6f7` | 页面底 / 分区底、代码块底 |
| bg-soft | `rgb(255 255 255 / 90%)` | 半透明导航栏 |
| text / mute / subtle | `#3c3c43` / 78% / 56% | 正文 / 次要 / 元信息 |
| border / hard / soft | `#c2c2c4` / `#b8b8ba` / `#e2e2e3` | 边框 / 硬分隔 / 发丝线 |
| control / hover | `rgb(142 150 170 / 10%)` / 16% | 图标按钮、kbd、chip |
| shadow | `rgb(0 0 0 / 15%)` | 阴影基色 |

**Dark**（`[data-theme=dark]`）

| Token | 值 |
| --- | --- |
| bg / bg-alt / bg-elv | `#1b1b1f` / `#161618` / `#202127` |
| text / mute / subtle | `rgb(235 235 245 / 86%)` / 60% / 38% |
| accent / accent-bg / accent-hover | `#2388f6` / `#0a75e9` / `#096fdc` |
| border / hard | `#3c3f44` / `#45484e` |
| control / hover | `rgb(101 117 133 / 12%)` / 18% |

两个值得沿用的决策：
1. 暗色不是简单反色 —— 正文用**带蓝的浅灰** `rgb(235 235 245)` 且降到 86% 不透明度，避免纯白刺眼。
2. 暗色 `accent-bg` 恰好等于亮色 `accent-hover`：强调色在两个主题里是同一色阶的两端，可共用变量。

### 2.4 字体与排版

```css
--ds-font-sans: -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Helvetica Neue', Arial,
  'Noto Sans', STHeiti, 'Microsoft YaHei', SimSun, sans-serif,
  'Apple Color Emoji', 'Segoe UI Emoji', 'Segoe UI Symbol', 'Noto Color Emoji';
--ds-font-mono: Consolas, Monaco, 'Andale Mono', 'Ubuntu Mono', monospace;
```

要点：**不引入 Web Font**，纯系统字体；中文兜底（华文黑体/雅黑/宋体）排在拉丁字体之后；
`-apple-system` 在 Mac 上落 San Francisco，"原生感"由此而来。

| 层级 | 字号 | 字重 | 行高 |
| --- | --- | --- | --- |
| Hero 标题 | 3.6rem (57.6px) | 700 | 1.5 |
| H1 | 2rem | 700 | 1.25 |
| H2 | 1.65rem | 700 | 1.25 |
| H3 / 区块标题 | 1.25rem | 600 | 1.4 |
| 导语 | 1.125rem | 400 | 1.7 |
| 正文 | 1rem | 400 | 1.7 |
| 导航 / 卡片正文 | 0.875rem | 400（下拉标题 500） | 1.7 |
| 元信息 / 标签 | 0.75rem | 400–500 | 1.5 |
| 代码 | 0.875rem (14px) | 400 | 1.6 |

**响应式降级阶梯**（避免移动端标题过大，值得照搬）：
Hero `3.6rem → 2.5rem (≤959) → 2.25rem (≤719) → 2rem (≤419)`；区块标题 `3rem → 2.5rem → 2.25rem → 2rem`。

### 2.5 间距 / 圆角 / 阴影 / 布局

- **间距**：基准 4px，节奏 `4 / 8 / 12 / 16 / 24 / 32 / 48`；嵌套容器用 8px，模块内边距用 16px（站上出现频次最高）
- **圆角**：`2px`(tooltip) · `4px` · `6px`(代码块/图片) · `8px`(卡片，最常用) · `10px`(大媒体) · `40px`(胶囊) · `9999px`(圆形)
- **阴影**

  | 值 | 场景 |
  | --- | --- |
  | `0 2px 8px rgb(0 0 0 / 5%)` | 卡片静默态 |
  | `0 4px 12px rgb(0 0 0 / 10%)` | 卡片 hover |
  | `0 8px 18px rgb(37 99 235 / 20%)` | 强调色发光 |
  | `0 12px 30px rgb(15 23 42 / 12%)` | 浮层 / 下拉 |
  | `0 18px 45px rgb(15 23 42 / 16%)` | 模态 / 大浮层 |

- **布局尺寸**

  | Token | 值 | 用途 |
  | --- | --- | --- |
  | `--ds-navbar-height` | 3.75rem (60px) | 顶栏；移动端 3.25rem |
  | `--ds-navbar-padding` | 1.5rem / 0.7rem | 横向 24px，纵向 11.2px |
  | `--ds-sidebar-width` | 18rem (288px) | 文档侧栏；移动端 16rem |
  | `--ds-content-width` | 780px | 文章正文 |
  | `--ds-page-width` | 1160px | 首页 / 宽容器 |

- **断点**：原站 `419 / 600 / 719 / 750 / 768 / 959 / 1100 / 1200 / 1280 / 1440`。
  承重的只有 **419（手机）/ 719（小平板）/ 959（平板，侧栏收起）/ 1440（宽屏）** 四个，新项目只保留 4 个。

### 2.6 组件形态（采样到的）

| 组件 | 关键样式 |
| --- | --- |
| 顶栏导航 | 60px 高、`bg-soft` 半透明、横向 24px 内边距；品牌区（logo + 站名 1.25rem）→ 中部导航 → 右侧动作区（搜索/主题/汉堡） |
| 导航项 | `0.875rem / 1.7rem`，默认 `text`，hover 与激活变 `accent`；下拉标题字重 500，箭头 hover 旋转 180° |
| Hero | 居中；渐变标题 + 1.125rem 导语 + 「开始学习→」CTA，上下 margin 1.8rem |
| Feature 卡片网格 | 换行 flex，`flex-basis: calc(33% - 3rem)`、`margin: .5rem`、`padding: 1rem`、`radius: .5rem`；hover 加阴影 + `translateY(-1px)`；桌面 3 列 |
| 文章页骨架 | 左侧栏（分组+折叠）→ 面包屑 → 标题 → 正文 → 页脚 meta（更新时间/字数）→ 上一篇下一篇；右侧 TOC 带当前项标记 |
| 代码块 | `radius: 6px`、`padding: 1rem 1.25rem`、`font-size: 14px`、行号槽宽 3rem、高亮底 `rgb(142 150 170 / 14%)` |
| 搜索框 | 高 56px、胶囊圆角 40px、focus 时 `inset 0 0 0 2px accent-soft`；`kbd` 快捷键提示（圆角 3px） |
| 页脚 | 版权 + 「基于 xx 构建」+ 备案号 + 二维码浮层（交流群/公众号） |

### 2.7 复用策略

**直接复用**：780px 正文宽 + 1160px 宽容器 · 4px 间距基准与节奏 · 卡片 8px 圆角 + 极轻阴影 ·
`0.3s ease` 统一过渡 · 系统字体栈与响应式字号阶梯 · 「一色四档」状态色结构 · 60px 顶栏 / 288px 侧栏骨架。

**改成自己的**：主色（`#096fdc` 是 Theme Hope 默认靛蓝，**建议换品牌色，只保留 token 结构**）·
Hero 渐变（可留，换配色或降饱和）。

**不要照搬**：原站基于 VuePress/主题的实现细节（`copy-code.js`、`anti-copy.js` 反复制脚本、DocSearch、
PrimeVue/Element Plus 痕迹）—— 你的栈是 React，重新实现；10 个断点收敛为 4 个；
**反复制脚本不要引入**（对个人站弊大于利）。

**建议的引入方式**（前端入口引入一次，改品牌色只需覆盖 `--ds-c-accent*` 四个变量）：

```ts
// src/main.tsx
import './styles/tokens.curated.css'
```

## 3. 信息架构与路由

```text
顶栏：关于我 │ 技术分享 ▾ │ 项目笔记 │ [搜索] [主题]
                      ├─ 分类：Java / Spring / MySQL / Redis / 并发 / 分布式 / AI·Agent …
                      └─ 标签：按技术栈横向聚合
                    （生活经验频道暂不实现；/admin 写入口不出现在公开导航里）
```

| 路由 | 页面 | 访问 |
| --- | --- | --- |
| `/` | **关于我**（个人主页 / 落地页） | 公开 |
| `/tech` | 技术分享：分类总览 + 最新文章 | 公开 |
| `/tech/c/:categorySlug` | 分类下的文章列表（分页） | 公开 |
| `/tech/:slug` | 文章详情 | 公开 |
| `/tags/:tagSlug` | 标签聚合列表 | 公开 |
| `/projects` | 项目笔记：项目卡片墙 | 公开 |
| `/projects/:projectSlug` | 项目详情 + 该项目下的笔记列表 | 公开 |
| `/projects/:projectSlug/notes/:slug` | 笔记详情 | 公开 |
| `/admin/login` | 后台登录页（Sa-Token） | 公开（受限流与失败锁定） |
| `/admin/*` | 写入口（新增 / 编辑 / 发布，见 [§8](#8-访问控制)） | **需登录** |
| `*` | 404 | 公开 |

导航约定：
- 顶栏固定 60px，半透明 + 模糊，滚动不跳变（沿用 `--ds-navbar-height`）
- 「技术分享」「项目笔记」用 hover 下拉列出分类/项目；移动端收进抽屉
- 顶栏**不放登录 / 头像入口**（没有账号体系），也不放后台入口 —— `/admin` 只靠直接访问 URL 进入

## 4. 页面内容清单

### 4.1 关于我 `/`（第一期核心页面）

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| Hero | 头像/形象图、姓名、一句话定位（渐变标题）、2–3 个关键词、CTA（看技术分享 / 下载简历 PDF） | `profile` |
| 技术栈矩阵 | 按「语言 / 框架 / 中间件 / 数据库 / 工具」分组，可带熟练度或年限，hover 高亮 | `skill` |
| 实习经历 | 竖向时间线：公司 · 岗位 · 起止时间 · 3–5 条职责与产出（建议量化） | `experience` |
| 项目经历 | 卡片墙：项目名、角色、技术栈标签、亮点一句话、GitHub/Demo 链接 | `project` |
| 数据统计 | 文章数、总字数、GitHub Stars 等（可静态，也可实时聚合） | 聚合查询 |
| 联系方式 | 邮箱、GitHub、博客、微信二维码浮层 | `profile` |
| 页脚 | 版权、备案号、构建信息 | 静态 |

设计参照：Hero 与数据统计沿用提取报告的布局语言（渐变标题 + 3 列卡片网格 + 极轻阴影），**配色换成自己的主色**。

### 4.2 技术分享 `/tech`

- **分类总览**：卡片列出全部分类（名称、文章数、一句话描述、最近更新时间）
- **列表**：文章卡片 = 标题 + 摘要（≤120 字）+ 分类/标签 + 日期 + 阅读时长 + 浏览量
- **详情**：面包屑 → 标题 → 元信息 → 正文 → 上一篇/下一篇 → 右侧 TOC（当前项高亮）
- **支撑能力**：Markdown 渲染、代码高亮 + 复制按钮、目录锚点、图片懒加载、暗色适配、SEO meta

### 4.3 项目笔记 `/projects`

- **项目卡片墙**：封面、项目名、状态徽章（进行中/已上线/归档）、技术栈标签、简介、仓库/演示链接
- **项目详情**：背景与目标、我的角色与贡献、架构图、踩坑记录、**关联笔记列表**

### 5.4 Gson 集成（重点，坑最多）

Spring Boot 默认用 Jackson，而本项目指定 Gson，必须显式替换：

```java
// 1) 依赖：引入 gson，并让 Gson 转换器优先
//    注意：Sa-Token 的 starter 会自带 sa-token-jackson（仅用于它的 Session/Redis 序列化），
//    因此不要把 Jackson 从 classpath 上彻底排除，而是把 Gson 转换器放到 converters 第 0 位
// 2) 注册转换器
@Configuration
public class GsonConfig implements WebMvcConfigurer {
  @Override public void configureMessageConverters(List<HttpMessageConverter<?>> converters) {
    Gson gson = new GsonBuilder()
        .setPrettyPrinting()                       // 生产可关
        .serializeNulls()                          // 让 null 字段也出现，前端类型更稳定
        .registerTypeAdapter(LocalDateTime.class, new LocalDateTimeAdapter("yyyy-MM-dd HH:mm:ss"))
        .registerTypeAdapter(LocalDate.class, new LocalDateAdapter("yyyy-MM-dd"))
        .registerTypeAdapter(Long.class, new LongToStringAdapter())   // 见下
        .create();
    GsonHttpMessageConverter c = new GsonHttpMessageConverter(gson);
    c.setSupportedMediaTypes(List.of(MediaType.APPLICATION_JSON));
    converters.add(0, c);                          // 放到最前，覆盖默认 Jackson
  }
}
```

**必须处理的 6 个坑**（每一项都写进 M1 的骨架任务）：

| 坑 | 后果 | 处理 |
| --- | --- | --- |
| 不认 Jackson 注解 | `@JsonProperty` / `@JsonFormat` 全部失效 | 统一改用 `@SerializedName`（或换成前端约定的 camelCase，少用注解） |
| 默认不处理 `java.time` | `LocalDateTime` 序列化成一堆嵌套字段 | 注册上面的 `LocalDateTimeAdapter`，格式 `yyyy-MM-dd HH:mm:ss`（服务器统一 `Asia/Shanghai`） |
| 默认不输出 `null` | 前端拿不到字段，`undefined` 判断遍地 | `serializeNulls()`，或统一由 `Result` 包装保证字段存在 |
| `Long` 精度 | 雪花 ID 超过 JS 安全整数会失真 | ID 一律**以字符串下发**（`LongToStringAdapter`），前端类型用 `string` |
| 枚举序列化 | 默认按 `name()` 输出，改名即破坏契约 | 用 `@SerializedName("PUBLIC")` 显式锁定，或用 int code |
| 泛型擦除 | 请求体里的 `Result<T>` 反序列化失败 | 后端只用 Gson 做**序列化**；请求体绑定到具体 DTO 类型，不用泛型包装 |

其他注意：Gson ≥ 2.10 才支持 Java `record`（本项目用 2.11+，DTO 可用 record）；Gson 不做字段级校验，
参数校验统一靠 `jakarta.validation` 注解 + `@Valid`。

### 5.5 Sa-Token 集成（后台认证，重点）

后台管理系统的登录态与会话由 **Sa-Token** 负责（官方文档：<https://sa-token.com>，本站已核对 Maven 与配置页）。

```xml
<!-- 认证鉴权（Spring Boot 3.x 专用 starter） -->
<dependency>
  <groupId>cn.dev33</groupId>
  <artifactId>sa-token-spring-boot3-starter</artifactId>
  <version>1.46.0</version>
</dependency>
<!-- 会话持久化到 Redis（重启不丢登录态） -->
<dependency>
  <groupId>cn.dev33</groupId>
  <artifactId>sa-token-redis-template</artifactId>
  <version>1.46.0</version>
</dependency>
<dependency>
  <groupId>org.apache.commons</groupId>
  <artifactId>commons-pool2</artifactId>
</dependency>
```

**六个必须知道的点**（都是官方文档明确写明的，不是猜测）：

| 点 | 说明 | 对项目的影响 |
| --- | --- | --- |
| **默认引入 Jackson** | `sa-token-spring-boot3-starter` 会自动引入 `sa-token-jackson` 作为 JSON 方案 | Jackson 会出现在 classpath 上。**HTTP 报文仍必须走 Gson** —— 靠「Gson 转换器放第 0 位」保证；不要指望 classpath 上只有 Gson |
| **没有 Gson 插件** | 官方 JSON 插件只有 jackson / jackson3 / fastjson / fastjson2 / fory-json / snack3 / snack4 | 想彻底不用 Jackson，只能换用 `sa-token-fastjson2` 之类插件或自定义序列化；**推荐方案是接受 Jackson 仅存在于 Sa-Token 内部** |
| **Session 存自定义实体会报错** | 多态反序列化安全机制，业务实体默认不在白名单 | **不要把业务实体塞进 SaSession**（只存 adminId 等基本值）；确需存则让实体实现 `SaJsonType`，并在 JSON 插件初始化**之前**注册 |
| **`token-name` 双重身份** | 默认 `satoken`，既是**前端提交 token 的 Header/参数名**，也是 **Redis 键前缀** | 设为 `jcpress-token` 之类项目专属值，避免与业务缓存键混淆 |
| **需要 Redis ≥ 6.0** | v1.46.0 的 `sa-token-redis-template` 使用了 `SET KEEPTTL` | Redis 版本必须 ≥ 6.0，否则报 `ERR syntax error` |
| **Spring Boot 3 的配置前缀变了** | Redis 连接信息用 `spring.data.redis.*`（不是 `spring.redis.*`） | `application.yml` 别写旧前缀，否则连不上 Redis 而 Sa-Token 静默退化 |

**推荐配置**

```yaml
spring:
  data:
    redis:
      host: 127.0.0.1
      port: 6379
      database: 1              # 与业务缓存分库，便于隔离与清理
sa-token:
  token-name: jcpress-token    # 请求头名 + Redis 键前缀
  timeout: 604800              # token 有效期 7 天（-1 表示永不过期）
  active-timeout: 1800         # 30 分钟无操作即需重新登录（后台场景合适）
  is-concurrent: true          # 允许同账号多端登录；要单端登录改 false
  token-style: uuid            # token 风格
  is-log: false                # 关掉框架日志噪音
```

**登录与拦截**

```java
// 登录：校验用户名密码后签发 token（返回值交给前端保存）
StpUtil.login(admin.getId());

// 拦截：只有 /api/v1/admin/** 需要登录，公开接口完全开放
@Configuration
public class SaTokenConfigure implements WebMvcConfigurer {
  @Override public void addInterceptors(InterceptorRegistry registry) {
    registry.addInterceptor(new SaInterceptor(handle ->
            SaRouter.match("/api/v1/admin/**")
                    .notMatch("/api/v1/admin/auth/login")   // 登录接口本身放行
                    .check(r -> StpUtil.checkLogin())))
        .addPathPatterns("/**");
  }
}
```

- 密码用 **BCrypt** 存哈希（可只引 `spring-security-crypto` 这一个工具包拿 `BCryptPasswordEncoder`，不引入 Spring Security 框架）
- 登出走 `StpUtil.logout()`；改密码后可调 `StpUtil.logout(adminId)` 让旧 token 立即失效
- Sa-Token 会把会话写到 Redis（键前缀取自 `token-name`），**业务代码不要手写这些键**，清理 Redis 时也要避开

```sql
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;   -- 单行表

CREATE TABLE `experience` (
  `id`              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `company`         VARCHAR(100) NOT NULL,
```

### 6.6 索引与约定

- 时间字段统一 `DATETIME`（不用 `TIMESTAMP`，避免 2038 与时区隐式转换问题），应用层统一 `Asia/Shanghai`
- 软删策略：内容类表用 `deleted` 标记，**唯一索引与唯一约束需注意软删后可重复创建** ——
  一期简单处理为"删除即改名 slug"或直接物理删除（个人站内容量小，推荐**物理删除 + 操作前确认**，减少心智负担）；
  若坚持软删，唯一索引需改为 `(slug, deleted)` 组合
- 分页统一用"传 `page`/`size`，返回 `total`"；数据量大后再考虑游标分页
- Flyway 迁移文件命名 `V1__init_schema.sql`、`V2__seed_data.sql`，**只增不改**

## 7. Redis 设计

| Key 模式 | 类型 | TTL | 用途 |
| --- | --- | --- | --- |
| `{token-name}:login:*` | String | 随 `timeout` | **Sa-Token 会话与 token 索引**（框架自动维护，键前缀取自 `sa-token.token-name`） |
| `login:fail:{username}` | String(计数) | 15m | 后台登录连续失败 5 次锁定，防撞库 |
| `rate:{ip}:{route}` | String(计数) | 60s | 接口限流（登录、写接口、上传、浏览量接口必加） |
| `view:article:{articleId}:{yyyyMMdd}` | Set | 2d | 浏览量去重（hash(ip+ua) 成员） |
| `rank:hot:articles:{yyyyMMdd}` | ZSet | 8d | 热门文章榜（score = 当日浏览量） |
| `cache:profile:home` | String(JSON) | 30m | 关于我首页聚合结果 |
| `cache:category:tree` | String(JSON) | 10m | 分类树 + 计数 |
| `cache:article:{type}:{slug}` | String(JSON) | 10m | 文章详情（写操作主动删除） |
| `idem:{key}` | String | 5m | 幂等键（表单重复提交） |

约定：
- **缓存失败不阻断读**：`try/catch` 包住缓存读写，失败直接查库
- **限流失败按安全优先**：Redis 不可用时**写入口直接拒绝**（`503`），公开读接口照常放行
- 缓存一致性用「**写后删缓存**」（Cache-Aside），不用双写
- `view_count` 走 Redis 计数，定时任务（每 5 分钟）批量回写 MySQL，避免每次浏览都写库
- **会话类 Key 由 Sa-Token 自己维护**：前缀取自 `sa-token.token-name`，**业务代码只读不写**；清理 Redis 时要避开这些键
- 建议给 Sa-Token 单独一个 `database` 索引（见 [§5.5](#55-sa-token-集成后台认证重点)），与业务缓存隔离

## 8. 访问控制

> **前提（已定，见 [§15 D9](#15-待确认决策)）**：**前台完全公开、访客无需登录**；
> **后台管理系统需要账号登录**，认证与权限使用 **Sa-Token**（集成细节见 [§5.5](#55-sa-token-集成后台认证重点)）。

### 8.1 两个平面

| 平面 | 范围 | 控制方式 |
| --- | --- | --- |
| **前台（读平面）** | 全部公开页面与只读接口：关于我 / 技术分享 / 项目笔记 / 搜索 / sitemap / RSS | **完全公开，零鉴权** —— 不注册、不登录、无 cookie、无 token |
| **后台（写平面）** | `/admin/*` 页面与 `/api/v1/admin/**` 接口：登录、新增、编辑、发布、上传图片 | **Sa-Token 账号登录**（用户名 + BCrypt 口令 → token） |

### 8.2 后台认证方案

| 项 | 方案 |
| --- | --- |
| 框架 | Sa-Token `sa-token-spring-boot3-starter` 1.46.0（**不用 Spring Security，也不用 JWT**） |
| 账号 | `admin_user` 表（见 [§6.1](#61-后台账号与审计)），只有管理员，**不开放注册** |
| 口令 | BCrypt 哈希存库；首次登录强制改密；口令强度校验 |
| 登录 | `StpUtil.login(adminId)` 签发 token，前端存 `localStorage` |
| 携带 | 请求头 `satoken`（名字由 `sa-token.token-name` 配置，本项目设为 `jcpress-token`） |
| 会话 | 存 Redis（`sa-token-redis-template`），服务重启不丢登录态 |
| 拦截 | `SaInterceptor` + `SaRouter.match("/api/v1/admin/**")`，登录接口自身放行 |
| 有效期 | `timeout: 7d`；`active-timeout: 30m`（后台闲置即需重新登录） |
| 多端 | `is-concurrent: true`（个人站允许手机 + 电脑同时在线）；若要单端登录改 `false` |
| 登出 | `StpUtil.logout()`；改密码后 `StpUtil.logout(adminId)` 使旧 token 立即失效 |
| 防爆破 | 登录失败计数（Redis `login:fail:{username}`）5 次锁定 15 分钟 + 登录接口限流 |

### 8.3 为什么前台不做账号体系

- 前台所有内容都是公开的，没有"只有登录才能看"的东西，账号只会增加注册、找回密码、会话安全的成本
- 没有前台账号，就**不存在越权读取他人数据**的问题 —— 这类隐私风险根本不存在
- 互动功能（评论、点赞）一期不做，也就不需要访客身份
- 将来若真要做"按人可见"的内容（生活经验），优先用**隐藏链接**或**共享口令**，而不是给前台加账号（[附录 C](#附录-c生活经验可见性备选方案)）

### 8.4 写平面必须守住的三条

1. **写接口只挂在 `/api/v1/admin/**`**，公开接口一律只读 —— 不给"顺手加个写接口"留口子
2. **鉴权统一在 Sa-Token 拦截器里做**，不在每个 Controller 里手写 `checkLogin()`（漏一处就是一个写洞）
3. **登录、写、上传三类接口都要限流**，写操作全部记 `admin_audit_log`（何时、IP、改了什么）

安全测试用例（M5 验收）：
未登录访问各写接口一律 `401`；登录接口错误口令 5 次后被锁定；登录接口有频率限制；
token 过期 / 伪造 token 被拒；超大或伪装类型的上传被拒；
**公开接口不存在任何写方法**（`POST/PUT/DELETE` 应返回 404 或 405）；前台页面无任何登录相关 Cookie。

## 9. API 契约

### 9.1 通用约定

- 前缀 `/api`，版本 `/api/v1`（第一版可先不加版本号，但路由常量集中管理）
- 请求/响应统一 `application/json; charset=utf-8`
- **统一响应体**

```json
{ "code": 0, "message": "ok", "data": {}, "traceId": "a1b2c3d4" }
```

- **分页响应**：`data = { "list": [], "page": 1, "size": 10, "total": 123, "pages": 13 }`
- **后台鉴权**：Sa-Token 的 token，请求头名 `satoken`（可配，本项目为 `jcpress-token`），仅 `/api/v1/admin/**` 需要；前台接口不需要任何凭据
- **ID 一律字符串**（Gson 的 `Long` 精度问题，见 §5.4）
- **时间格式** `yyyy-MM-dd HH:mm:ss`（服务器时区 `Asia/Shanghai`）

**错误码**

| 区间 | 含义 | 示例 |
| --- | --- | --- |
| `0` | 成功 | — |
| `400xx` | 参数错误 | 40001 参数校验失败 |
| `401xx` | 未登录 / 登录失效 | 40101 未登录、40102 token 过期或无效、40103 登录失败次数过多 |
| `404xx` | 不存在 | 40401 文章不存在 |
| `409xx` | 冲突 | 40901 slug 已存在 |
| `429xx` | 频率限制 | 42901 请求过于频繁 |
| `500xx` | 服务端错误 | 50000 系统异常 |

HTTP 状态码与 `code` 同时正确（401 就返回 HTTP 401，不要一律返回 200 再靠 `code` 判断）。

### 9.2 公开接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查（含 DB/Redis 探活） |
| GET | `/api/v1/profile` | 关于我首页**聚合**接口（profile + skills + experiences + featured projects + stats） |
| GET | `/api/v1/categories?type=TECH` | 分类树（含各分类文章数、最近更新时间） |
| GET | `/api/v1/tags` | 标签列表（含计数） |
| GET | `/api/v1/articles` | 列表，参数 `type` `categoryId` `tagSlug` `keyword` `page` `size`；**不返回正文** |
| GET | `/api/v1/articles/{slug}` | 详情，返回 Markdown 原文 + 元信息 + TOC 数据 |
| GET | `/api/v1/articles/{slug}/adjacent` | 上一篇 / 下一篇（同类型、同分类范围内） |
| GET | `/api/v1/projects` | 项目列表 |
| GET | `/api/v1/projects/{slug}` | 项目详情 |
| GET | `/api/v1/search?q=&type=` | 搜索（MySQL 全文索引，无命中降级 `LIKE`） |

| GET | `/api/v1/sitemap.xml` | 站点地图（或由预渲染阶段生成静态文件） |

### 9.3 后台接口（写平面，需 Sa-Token 登录）

**认证类**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/admin/auth/login` | `{username, password}` → 返回 token（此接口无需登录，但受限流与失败锁定） |

| GET | `/api/v1/admin/auth/me` | 当前登录账号信息（不含口令哈希） |

**内容管理类**（全部需要登录）

| 方法 | 路径 | 说明 |
| --- | --- | --- |

## 10. 后台管理系统

> **决策已定**（见 [§15 D8](#15-待确认决策)）：需要一个管理端，但**不在一期实现完整后台**。
> **后台需要账号登录**，认证用 **Sa-Token**（见 [§8](#8-访问控制) 与 [§5.5](#55-sa-token-集成后台认证重点)）。
> 本节定义形态、边界与升级触发条件；完整后台放在 M7。

### 10.1 为什么不做完整后台

- 完整 CRUD 后台（文章 / 分类 / 标签 / 项目 / 用户 + 编辑器 + 图库 + 统计）工作量约为公开站的 **40–60%**
- 本站是**单作者、单管理员**，内容以 Markdown 为主；技术文章与项目笔记本来就该有版本管理
  （写错能 diff、能回滚），"仓库写 md + 导入"比富文本后台**更好**，不是将就
- 后台是攻击面：多一套鉴权入口、上传接口与管理接口，就要多一套限流、审计与测试

### 10.2 内容维护分工（按"谁维护、多久改一次"分配）

| 内容 | 变化频率 | 一期怎么维护 | 升级为 UI 的触发条件 |
| --- | --- | --- | --- |
| 技术分享文章 | 高（每周） | 仓库写 `content/tech/*.md` + front-matter 导入；或用后台写入口 | 内容 > 50 篇，或想在手机上写 |
| 项目笔记 | 中 | 同上（`type=PROJECT`，同一导入器 / 同一写入口） | 同上 |
| 简历数据（技能 / 实习 / 项目） | 极低（一年几次） | Flyway seed / 直接 SQL | 觉得改 SQL 麻烦时（可选） |
| 图片 | 中 | 后台的上传接口 + 编辑器粘贴上传 | 需要图库 / 复用 / 清理时 |
| 后台账号 | 极低 | 数据库手工维护（**不开放注册**） | 不需要 |
| 生活经验 | — | **暂不实现** | 真要做时先定可见性方案（[附录 C](#附录-c生活经验可见性备选方案)） |

### 10.3 三步走（触发式升级）

| 步骤 | 时间点 | 交付物 | 关键要求 |
| --- | --- | --- | --- |
| **第一步：Markdown 导入器** | M1 | 同仓库 `content/**/*.md` + 一条命令 `--import=<dir>`（复用同一个 jar，加 profile） | 按 `(type, slug)` 幂等；支持新增与更新；**不删除已发布内容**；支持 `--dry-run`；front-matter 校验失败则整批回滚 |
| **第二步：后台登录 + 写入口** | M5 | `/admin` 登录页 + 写入口单页（Markdown 编辑器 + 分类 / 项目选择 + 存草稿 / 发布 + 图片上传），由 **Sa-Token** 保护 | 手机可用；未登录访问一律 401；发布后清理相关缓存；写操作记审计日志 |
| **第三步：完整后台** | M7（按需） | 文章列表与筛选、分类标签管理、项目关联、访问统计、图库 | 只在"真正感到疼"时做；先对照 10.2 的触发条件判断 |

**front-matter 约定**

```markdown
---
title: Spring Boot 里替换掉 Jackson 改用 Gson
slug: spring-boot-gson
type: TECH            # TECH / PROJECT（LIFE 预留）
category: spring      # category.slug（TECH 必填）
project: jcpress      # project.slug（PROJECT 必填）
tags: [Java, Spring Boot, JSON]
summary: 一段不超过 120 字的摘要
cover: /uploads/xxx.png
status: PUBLISHED     # DRAFT / PUBLISHED / ARCHIVED
publishedAt: 2026-10-01 09:00:00
---

正文……
```

### 10.4 技术形态（若做第三步）

- **同一个 Vite 应用 + `/admin` 懒加载路由**，不拆第二个前端工程：共享 API 客户端与类型，部署只有一个产物
- 用 `manualChunks` 把后台依赖单独分包，普通访客不会下载到后台代码
- **后台可以用组件库**（Ant Design / Arco），但与公开站**视觉隔离**：公开站坚持提取来的克制风格，
  后台走标准管理台样式，两套 token 不要互相污染
- 后端独立命名空间 `/api/v1/admin/**`，统一由 **Sa-Token 拦截器**校验登录，写操作记审计日志
- 编辑器：Markdown 编辑器（CodeMirror 6 或 `@uiw/react-md-editor`）+ 图片粘贴上传
- **后台登录态与前台完全隔离**：`/admin` 未登录时跳 `/admin/login`，前台页面不受任何影响
  （前台不发 token、不读 token，也不因为后台登录状态而变化）

### 10.5 安全清单（做后台时逐条核对）

- `/admin` 不做 SEO、不进 sitemap、`robots.txt` 禁止收录
- `/actuator/**` 不暴露公网，仅 Nginx 内网可达
- 上传接口：校验 MIME + 扩展名 + 大小上限，重命名落盘，禁止可执行类型与路径穿越
- **登录接口**：限流 + 失败锁定（Redis `login:fail:{username}`）；口令 BCrypt 存库；首次登录强制改密
- **token 收敛**：`timeout: 7d` + `active-timeout: 30m`；改密后 `StpUtil.logout(adminId)` 让旧 token 立即失效
- 写与上传接口加限流；管理操作全部记 `admin_audit_log`（何时、IP、改了什么）
- 可选加固：`/admin` 限定固定 IP；`is-concurrent: false` 强制单端登录（新登录挤掉旧登录）
- **明确不做**：独立后端服务、前台账号体系、多角色权限矩阵、工作流审批

```text
├── backend/Dockerfile     # 多阶段：maven 构建 → JRE 21 运行
└── .env.example
```

- **环境隔离**：`application-dev.yml` / `application-prod.yml`，敏感值全部占位为环境变量
- **数据库迁移**：容器启动时 Flyway 自动执行；生产迁移前先备份
- **备份**：`mysqldump` 每日定时 + 保留 7 天 + 异地一份；Redis 开 AOF（会话数据可丢，缓存可重建）
- **Sa-Token 会话**：登录态存 Redis（服务重启不掉线）；Redis 必须 **≥ 6.0**（1.46.0 使用 `SET KEEPTTL`）；
  Spring Boot 3 的 Redis 连接配置前缀是 `spring.data.redis.*`（不是 `spring.redis.*`）
- **后台初始账号**：首次部署用 Flyway seed 的管理员登录，登录后立即改密
- **日志**：Logback 按天滚动，保留 30 天；错误日志单独文件
- **监控**：Actuator `/actuator/health` 暴露给 Nginx 内网；外加上一层可用性探测（如 Uptime Kuma）
- **HTTPS**：Let's Encrypt 自动续期；HTTP 强制跳转
- **备案**：国内节点需 ICP 备案（页脚展示备案号）；未完成前先海外节点 + CDN

## 14. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| **Gson 与 Spring Boot 适配**：不认 Jackson 注解、默认不处理 `LocalDateTime`、默认不输出 null、`Long` 精度 | 字段对不上、时间错乱、ID 失真 | §5.4 的六个坑在 M1 一次性处理完，并写单测 |
| **后台账号被撞破**（弱口令 / 暴力破解 / token 泄露） | 别人能改你的站 | BCrypt 存密 + 强口令；登录失败锁定与限流；`timeout` + `active-timeout` 收紧有效期；写接口只挂在 `/api/v1/admin/**`；可选 IP 白名单 |
| **SPA 的 SEO 劣势** | 技术文章搜不到 | 预渲染（D3）+ sitemap + `BlogPosting` 结构化数据 |
| **Sa-Token 与 Gson 的边界**：starter 默认引入 Jackson；Session 里塞业务实体会触发类型白名单报错 | 误以为全站序列化器被换掉；反序列化直接报错 | HTTP 报文仍由 Gson 转换器优先处理（放 converters 第 0 位）；**不往 SaSession 塞业务实体**，只存 adminId；确需存时实现 `SaJsonType` 并在插件初始化前注册 |
| **Markdown 渲染 XSS** | 脚本注入 | `rehype-sanitize`；后端存 MD 原文，不信任 HTML |
| **内容产出断档** | 站点变空壳 | 结构上支持短笔记降低单篇成本；项目笔记与技术文共用管线 |
| **国内部署备案** | 无法使用国内域名/服务器 | 尽早确认域名与备案；未备案先用海外节点 + CDN |
| **Redis 单点** | 后台登录态与缓存不可用 | 读路径缓存失败降级直查 MySQL；Redis 不可用时后台需重新登录（可接受），**写入口按安全优先拒绝** |
| **设计照搬过度** | 与参照站撞脸、被误认为抄袭 | 只复用 token 结构与数值体系，主色与视觉签名自定；详见 §2.7 |

## 附录 C：生活经验可见性备选方案

第一期不做生活经验频道（[§15 D2](#15-待确认决策)）。将来若要恢复，按性价比排序：

| 方案 | 做法 | 成本 | 适用 |
| --- | --- | --- | --- |
| **隐藏链接** | 用不可枚举的长随机 slug；不进列表、不进 sitemap、`robots noindex`、搜索与相邻文章都不漏 | 极低（服务端多一个 `unlisted` 标记） | 发给特定的人，靠"链接不外传"保密 |
| **共享口令门** | 一套共享口令，验证后签发 HMAC 签名的 Cookie（30 天）；服务端拦截 `/life` 路径 | 低（一个过滤器 + 一个 Cookie） | 想让家人 / 朋友长期可读，又不想建账号 |
| **复用后台账号** | 直接复用 Sa-Token 的后台登录态，`/life` 要求已登录 | 极低（复用已有能力） | 只给"有后台账号的人"看 —— 但后台账号是本人在用的管理身份，语义上不建议混用 |
| **按人授权（前台账号体系）** | 访客注册登录 + 角色 + 内容可见性分级 | 高（等于把一次删掉的东西全加回来） | 只有多人协作 / 公开投稿时才值得 |
| **纯公开** | 与其他频道一样正常收录 | 零 | 其实并不介意被看到 |

无论选哪种，都要注意**全链路一致**：列表、详情、搜索、标签聚合、RSS、sitemap、
相邻文章（上一篇 / 下一篇）都必须走同一套规则 —— **相邻文章是最容易漏的地方**。
